# 节奏与交接：消除 PPT 感

症状：**"两页之间切换太慢，不灵动"**。听起来像翻幻灯片 —— 一页停住 → 换页 → 再停住。
这条症状有三个根因，全都可量化、可修。

## 1. 根因

### 根因 A：缓动形状让开头"看不见动"（最常被误判成"时长太长"）

同样 1.0 秒的位移，**前 25% 的时间里走了多少**：

| 缓动 | 25% 时间点已走完 | 手感 |
| --- | --- | --- |
| `ease-in-out-quart` | **3%** | 迟钝：你以为它没动 |
| `ease-in-out-cubic` | 6% | 迟钝 |
| `ease-out-cubic` | 58% | 轻快 |
| `ease-out-expo` | **82%** | 干脆，软着陆 |
| `ease-out-circ` | 79% | 机械干脆 |

所以"慢"多半不是 duration 的问题，而是**把两端都慢的缓动放在了换场上**。
`ease-in-out` 天生读起来像"过渡动画"—— 它就是 PPT 转场的手感来源。

### 根因 B：先出后进，中间留空档

反例（真实发生过的）：主体在 11.5s 出场完毕，下一个主体 12.4s 才开始入场 ——
**0.9 秒里画面几乎没事发生**。观众读到的就是"这一页讲完了，等下一页"。

空档是可测的：`taste_check.py --rhythm` 会报出"最长死拍"。

### 根因 C：整帧替换，而不是共享元素

整块擦除 / 整块缩放 / 整块淡入 = 换页。真正灵动的做法是让**一个东西从上一拍活到下一拍**，
由它承担变换（数字 → 地形、点 → 墨点 → 量尺、表 → 场）。页与页之间就没有边界可被感知。

## 2. 解法

### 2.1 重叠交接（最高性价比）

出口和入口**重叠 40–60%**，任意时刻至少有一条轨道在动：

```
0.90–1.20  A 主体离场        ease-in-quart
1.05–1.55  B 主体入场        ease-out-expo     ← 与 A 重叠 0.15s
1.20–1.60  A 的残留 / B 的次级动作
```

规则：**相邻两个状态之间的空档 ≤ 0.15s**；"exit 完成之后才开始 enter"是禁止写法。

```js
// 交接：两段窗口重叠，中间不留空场
const OUT0 = 0.90, OUT1 = 1.20;              // 出口短而硬
const IN0  = 1.05, IN1  = 1.55;              // 入口与出口重叠 0.15s
const o = INQ(P(t, OUT0, OUT1));             // ease-in-quart：起慢出硬
const i = EXP(P(t, IN0,  IN1));              // ease-out-expo：起快软着陆
a.style.opacity = String(1 - o);
b.style.opacity = String(i);
// 体感：整个换场"看起来"只有 0.65s，因为 0.90–1.20 这段画面一直在变
```

### 2.2 缩短整帧动作，把时间留给"被读"

把"动作"和"停留"分开算：

| 层 | 目标时长 |
| --- | --- |
| 元素级状态切换（高亮、位移、显隐） | 0.25–0.4s |
| 整帧级变换（镜头级大动作） | **0.5–0.9s**，绝不超过 1.2s |
| 停留 | 只停在"已经到位、正在被看"的画面上，且停留期间环境与次级动作**必须仍在动** |

1.3–1.5 秒的整帧变换（比如让一个数字放大铺满画面）本身不算错，但要**拆分**：
大位移用 0.6s 走完，剩下的 0.7s 交给它内部的次级动作（纹样展开、材质收紧、余振）——
否则观众看到的是一段"匀速爬行"。

### 2.3 不要连续同向

连续两次换场都从左往右滑 → 观众立刻读成翻页。相邻换场**换轴或换向**（上一拍从左侧来，
下一拍从上侧落），眼睛才有走位。

### 2.4 多轨错相

不要让所有东西同时停：A 在 0.90 停、B 在 1.15 停、C 在 1.40 停，形成余波。
"同时停"是静帧感的第二大来源。

## 3. 测量：把"PPT 感"变成数字

```bash
python scripts/taste_check.py <video.mp4> --rhythm
```

输出：逐 0.5 秒的画面变化柱状图 + 四个指标。

| 指标 | 含义 | 灵动 | 有 PPT 感 |
| --- | --- | --- | --- |
| 冻结帧比例 | 相邻帧几乎相同（Δ<1.0/255）的占比 | ≤ 35% | > 45% |
| 最长死拍 | 连续几乎不动的时长 | ≤ 0.5s | > 0.8s |
| 每秒变化均值 | 运动强度（也要过 ≥2.2 的验收闸门） | ≥ 3.0 | < 2.2 |
| p90 ÷ 均值 | 节奏有没有起伏 | ≥ 1.5 | < 1.2（一条平的线） |

柱状图读法：柱子应该**此起彼伏、并且没有连续两个空格**。如果你看到
`##....##....####` 这种，就是"一段动、一段死"，也就是 PPT。

### 3.1 像素看不到的那一半：审时间轴

环境运动（呼吸、漂移、残留点）会把"每秒变化"一直垫在阈值之上 —— 所以一支节奏很慢的片子
也可能过像素检查。"两页之间切换太慢"是交接结构的问题，只能审时间轴：

```bash
python scripts/beat_audit.py project.json      # 读 data.beats，出错时 exit 1
```

在 `data.beats` 里给每一拍写两段窗口：`in` 是这一拍进场的东西，`out` 是被它换下去的东西。
审计会报四类问题：

| 报告 | 含义 | 阈值 |
| --- | --- | --- |
| `GAP` | 上一拍结束到下一拍开始之间的空档 —— 先出后进，PPT 的病根 | > 0.15s |
| `weak handoff` | 两拍重叠太少，视觉上仍然是换页 | < 0.15s |
| `too long` | 单个窗口太长，读起来像一段过渡动画 | > 1.2s |
| `hole` | 同一拍里 in 已经结束、out 还没开始 | > 0.2s |

它还会打一张时间轴图：`#` 的位置就是"出口和入口同时活着"的时刻。那些列越多，越不像翻页。
实测：一支 10 秒开篇被它抓出 1 处 1.05s 的 GAP、3 个过长窗口和 4 处弱交接 —— 全都不是
缓动参数能修的。

## 4. 交接清单（写完场景后逐条过）

- [ ] 每个换场，出口窗口的结束时间 **晚于** 入口窗口的开始时间（重叠 ≥40%）
- [ ] 出口用 `ease-in-quart`，入口用 `ease-out-expo`；没在换场上用 `ease-in-out`
- [ ] 整帧变换 ≤ 1.2s，其中 ≥70% 的变化量集中在前 30% 的时间里
- [ ] 相邻换场不同向／不同轴
- [ ] 每个停留段里，环境和次级动作仍在动
- [ ] 有一个共享元素穿过至少一个换场（不需要重画，只需要变形/迁移）
- [ ] `beat_audit.py` 无 GAP、无过长窗口、交接重叠 ≥ 0.15s
- [ ] `taste_check.py --rhythm` 四个指标全部落在"灵动"列

## 5. 已发生过的反例（别再犯）

- 34 秒那支：带子 11.50s 退完、下一次入场 12.40s 开始 → 0.9s 死拍；冻结帧 68%。
- 同一支：转轴、放大、回退三处整帧变换都是 1.3–1.5s 且两端慢 → 读起来像三段"过渡动画"。
- 10 秒开篇：冻结帧 56%，1.9–2.6s 的"停一下"过头了 —— 应该是 0.3s 的停顿，不是 0.7s 的空场。

改法固定：**把每处"等它退完再进"改成重叠交接，把两端慢的缓动换成 out-expo，把超长的整帧变换拆成"0.6s 位移 + 0.7s 次级"**。
