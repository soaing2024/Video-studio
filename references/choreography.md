# 编排规则（Compose, don't select）

这份文件是给 AI 代理的执行规范。它只解决一件事：

> **不要把画面当成"从一套模板里挑一个"，而是每一拍现写一套编排。**（本技能已经删掉了那七个骨架）
> 模板是参考实现，不是要填的空。同一套骨架在第二支片子里出现，它就是 AI 味。

立论不是审美洁癖，是可测量的：模板复用的失败形态是**静帧没设计** —— 关掉动效看那一帧，
如果它只是"居中大标题 + 一行副标题"，那这支片子的画面从来就没被设计过，动效只是在给一张
没设计的画面加装饰。规则、闸门、查重表都是为了守住这一条。

规则来源（选择性吸收，出处见 §10）：动效网页设计里的「不用模板编排自定义设计」、
「AI 味闸门」、「多轨时间轴编排」、「动效 token」，前端设计里的「每页一个签名、两遍批判」，
以及演示文稿设计里的「一页一个主张、一个构成而不是一堆面板」。

---

## §0 一镜到底：整片是一个镜头

**没有分段、没有切、没有转场。** 一个项目 = 一个场景文件 + 一个总时长，整片从 t=0 连续到结束。
所以"换场"不再是剪辑动作，而是**镜头内的变换**：把主体移出画面再让新主体进来、把一个物件变成
下一个、用画面里的元素横向扫过完成替换、或者用一次明暗呼吸当节拍。

成本上只剩一个杠杆：`hold` —— 声明"这几秒画面真的不变"，渲染器只渲一帧、其余帧复用
（`"hold": [[5.0, 10.0]]`）。它是原来 `still` 段落的等价物，也是长片唯一的省钱办法。

## §0.1 三条硬立场

1. **每一拍现写场景**。每一拍是一个独立的 HTML/CSS/JS 场景，只暴露 `window.seek(t)`。
   只有三条不可破的约束：**离线**（不联网）、**`seek(t)` 是纯函数**（无 `requestAnimationFrame`、
   无 `Date.now()`、无 CSS transition）、**帧精确**（同一个 `t` 必然同一帧）。
2. **技能不提供模板。** 原来的七个骨架已经删除——它们曾经的价值只是"告诉你 `seek(t)` 长什么样、`Scene`/`Anim`/`Kit` 怎么接"。
   现在每一拍只有一个空白场景文件（`vs.py init` 生成），画面完全由你现写。
3. **静帧优先于动效**。先让这一拍在**关掉动效**时能站住，再让它动起来。
   这一条同时是验收标准（见 §6 静帧闸门）。

## §1 编排流程（七步，创造发生在执行中）

不要指望"读文档就有灵感"。文档是物理和约束，不是答案。答案来自流程：

1. **定沟通任务**。一句话：*到这一拍结束，观众应该「明白/相信/想看下去」什么，因为「这一句」。*
   写不出来说明这一拍不该存在。对应 `brief` 的 `intent`（它是必填项，空着 `compile` 直接报错）。
2. **定宏观结构**（§2）。整片先选一种形态，再谈每一拍。结构定错，后面每一拍都会别扭。
3. **抽取主题的物理**。把题目里的名词翻成动作：*排队* → 队列推进/挤出；*光合* → 转向与充能；
   *编译器* → 解析/改写/落地。动效意图从物理来，不从"好看"来。
   - 例：题目是"一个把长视频做便宜的流水线" → 物理是**静态保持**：大多数帧不动，只有**换页**在动；
     动效意图就是"少动、但每次动都换一页"。
4. **发明签名机制**（§3 的六个算子），先出 **3 个候选**（协议见 §1.5），然后按三条筛：
   (a) 不在查重表（§7）里；(b) 能用纯函数实现；(c) 一句话说得清。
   再用"砍掉一个配饰"的规矩收尾：全片只留一个记忆点。
5. **定视觉系统**（§4）：色三档、字号跳跃、字体双角色、纹理、网格。数值先定，再写代码。
6. **逐拍编排**（§5 时间轴铁律 + §6 闸门）。每拍写清：意图 / 屏上文字 / 构图骨架 /
   运动 / 时长 / **money frame 在哪一刻**。
7. **两遍批判**。第一遍：静帧能不能站住？第二遍：动起来之后，这一拍有没有"死拍"？
   命中闸门就改结构，不是改参数。

## §1.5 结构搜索：先出三个，再挑一个（不要一次成型）

单次生成的审美方差很大：同一个想法出来的东西，可能一个能用一个平庸。**改 prompt 解决不了方差，
多出几个候选再挑才能。** 但候选必须**结构不同**：

- 不同的**宏观结构**（§2）或不同的**生成算子**（§3）；
- 不是同一版式换配色、换字号、换缓动——那是同一个方案的三件衣服。

**便宜的做法**：三个候选**都只做到 pass 1（骨架）**——只放块面和主体位置，不写文字内容、不选颜色、
不做动效。然后用 `vs.py rehearse` 或 `vs.py scrub` 横向看一次，选一个继续做 pass 2-5。
骨架阶段返工几乎零成本，成品阶段改结构等于重写。

**打分四条**（同分就选元素更少、留白更大的那个）：

1. **静帧站得住**：关掉动效、缩到 160px，结构还读得出来吗？
2. **一句话讲得清**：说不清这一拍在干什么，说明结构没想清。
3. **不在查重表里**（§7）：撞了就换。
4. **可实现**：能用 `seek(t)` 的纯函数写出来。

**工具**：`python vs.py shots "<这一拍的 intent>"` 直接给三个结构不同的候选（宏观结构 / 算子 /
版式 / 运动手段各不相同）与上面这套流程；也可以 `--brief brief.json --beat 2` 从分镜表里取 intent。

**落选的要记账**：没选中的结构写进 §7 查重表，下一支片子不能再撞同一个骨架。

## §2 宏观结构（先选形态，再谈镜头）

| 形态 | 片子是什么 | 动效住在哪 | 可测特征 |
| --- | --- | --- | --- |
| **单一场景 Single scene** | 一个空间，观众在里面移动 | 场景本身就是动效 | 长镜头、摄像机一路走、极少切 |
| **幕 Acts** | 3–5 个段落，每段一个主张 + 一张 money frame | 每幕一个机制，共享同一套语汇 | 段落边界清晰、每幕有落点 |
| **编辑式 + 定点节目 Editorial + set-pieces** | 大部分是可读内容，动效只来 2–4 次且都有意义 | 段落之间的标点 | 中等时长、文字为主、动效稀缺 |
| **索引 / 档案 Index** | 可浏览的清单 | 状态切换之间 | 每屏信息量小、切换多 |
| **单屏仪器 Single instrument** | 一屏一个可玩的东西，没有"切"这个动作 | 整个片子 | 单镜头、无切换 |

选错形态的典型症状：用"幕"的形态做单一机制（每幕都在重复同一个动作），
或者用"单一场景"做信息密集型内容（观众还没读完就过去了）。

## §3 签名机制：六个生成算子

题目里的每个主题都有自己的原生动作，别的主题没有。把它挖出来，再过一遍算子：

| 算子 | 动作 | 例子 |
| --- | --- | --- |
| **直译物理** | 把主题字面上的物理行为变成编排 | 讲"压缩"：画面真的被挤扁再回弹，文字被挤到边缘 |
| **输入反转** | 换掉"谁控制谁" | 不是进度条推动画面，而是画面推动进度 |
| **维度替换** | 把一个量映射到没料到的维度 | 时间流逝 → 颜色温度；数据量 → 字号；错误率 → 抖动频率 |
| **介质想象** | 把整支片子放进一种介质里 | 蜂蜜里（一切滞后）、真空里（没有回弹）、磁场里（同极相斥） |
| **杂交** | 把两个不相关的原型焊在一起 | 翻页 × 重力；擦洗 × 音高；钟摆 × 打字 |
| **破坏规则** | 违反一个默认约定，并且物理化它 | 不是"淡出结束"，而是画面被抽走；不是"从左到右生长"，而是从中心塌陷 |

规则：**先出 3 个候选，再选**。选中的那个要能一句话讲清，并且要能被 `seek(t)` 纯函数实现。
选完把**没选中的**和整片的记忆点写进 §7 查重表 —— 下一支片子不能再撞。

## §4 视觉系统（数值先定，再写代码）

### 4.0 逐步构图：五个 pass，一个 pass 一道闸门

一帧不是一次写完的。按顺序搭，每一步有自己的闸门，过不了就停在那一步改：

| pass | 做什么 | 闸门 |
| --- | --- | --- |
| 1 骨架 | 只放块面与主体位置：焦点在哪、占多大、视线怎么走 | 缩到 160px / 眯眼看，结构仍然读得出来 |
| 2 层级 | 文字层级与字号跳跃（主 / 次 / 三级，跳跃 ≥ 2.5×），落在安全区内 | 第一眼落在主元素；去掉颜色层级依然成立 |
| 3 色彩 | 三档色彩预算（底 / 主 / 强调），正文对比度 ≥ 8:1、次要 ≥ 4:1 | 转成灰度后层级没塌 |
| 4 运动 | 七行动作规格、一个承担时间的元素、交接重叠 40-60%（§5、§6） | `beat_audit.py` 通过；关掉动效静帧仍然成立 |
| 5 质感 | halation / grain / vignette / bloom 这些最后 5% | 关掉 finish 结构不变差——它只加分，不救结构 |

两条纪律：

- **3-5 被 1-2 挡住。** 结构没立住就加颗粒和辉光，只是把同一个坏结构做得更贵。
- **检查用 `scrub` / `rehearse`，不要用 `preview`。** pass 阶段要判断的是结构和节奏，廉价排练就够；
  `preview` 只回答一个纸面上说不清的具体疑问。

---

### 4.1 色彩：三档，不是彩虹

| 档 | 占比 | 是什么 |
| --- | --- | --- |
| 画布 Canvas | ~60% | 质地与底色。哑光漆、未漂白的亚麻纸、混凝土灰 —— 说得出材质 |
| 结构墨 Structural ink | ~30% | 高对比的可读文字色 |
| 电流 Accent | ~10% | **只在状态变化时闪**的高饱和色，不是背景装饰 |

两三个色相加一个中性色就是一套配色；**光谱不是配色**。紫蓝渐变（`#6366f1 → #a855f7`）
是最可靠的"AI 味"标志，除非题目明确要求，不要用。

### 4.2 字号：跳跃就是设计

获奖动效页的实测中位数：**最大字 ÷ 正文字 ≈ 8×**（区间 3.3×–14×）。
本项目里对应的做法：一屏里要么有一个**巨大**的元素（占宽 40% 以上的字或形），
要么整屏都是小字（编辑式），**中间状态最像模板**。

- 反面清单：所有元素都落在 16–48px 这个量级里 —— 没有对比，就没有设计。
- 文字不超过两行；宁可改文案，不要缩小字号。
- 竖屏安全区：顶部 12%、底部 20% 会被平台界面压住。

### 4.3 结构即信息

编号、眉标、分隔线、角标 —— 只有当它们**编码了真实信息**时才画。
"01 / 02 / 03" 只有在内容真的是有序过程（或时间线）时才有意义。
用装饰冒充结构，是模板的第二个特征。

### 4.4 一个构成，不是一堆面板

**不要**卡片网格、药丸标签、徽章、按钮状的文本框、标签页、导航条、仪表盘式的密集面板。
这些"组件库质感"会让画面看起来像 UI 截图，而不是被设计过的画面。
一屏一个焦点、一块平面、一条阅读路径。

### 4.5 版式形态

不要每拍都是"居中一列"。获奖页面的版式是**双峰**的：要么极简（一个元素，大量留白），
要么极繁（满幅、密集、图层叠压）。中间那种"标题+副标题+两行说明"的居中列，是默认值，
不是选择。

## §5 动效系统

### 5.1 时长档位（说不出意图就砍半）

| 档 | 值 | 用途 |
| --- | --- | --- |
| instant | 80–100ms | 微反馈 |
| fast | 150–200ms | 状态切换、高亮 |
| standard | 280–350ms | 元素展开、位移 |
| medium | 400–500ms | 段落揭示、画面进入 |
| slow | 600–800ms | 全屏进入、主角揭示 |
| cinematic | 1000–1400ms | 冷开场、幕布、戏剧性入场 |
| ambient | 持续 | 背景循环、呼吸 |

### 5.2 缓动字典（写进代码就用这些值）

| 名字 | cubic-bezier | 性格 |
| --- | --- | --- |
| ease-out-expo | `0.16, 1, 0.3, 1` | 快进 → 软着陆。**揭示的默认值** |
| ease-in-expo | `0.7, 0, 0.84, 0` | 慢起 → 硬出。**只用于离场** |
| ease-in-out-quart | `0.76, 0, 0.24, 1` | 对称平滑。循环动效 |
| ease-out-back | `0.34, 1.56, 0.64, 1` | 轻微过冲。俏皮 |
| ease-out-circ | `0, 0.55, 0.45, 1` | 极快减速。机械感 |
| ease-sharp | `0.65, 0, 0.45, 1` | 硬着陆。开场重击 |
| linear | `linear` | **只给时间轴和扫描类** |

弹簧（`Anim.spring(p, stiffness, damping)` 的档位）：gentle 100/15、default 200/22、
snappy 350/28、bouncy 200/10、heavy 150/35、stiff 500/40。

### 5.3 错开（stagger）

| 场景 | 值 |
| --- | --- |
| 密集网格 | 0.04s |
| 常规列表 | 0.07–0.08s |
| 逐行文字 | 0.08–0.1s |
| 戏剧性阶梯 | 0.12–0.18s |
| 单一决断的动作 | 0 |

文案块按**阅读顺序**错开，且**最轻的最后**（最后落地的东西压在最完整的画面上）。
段落级的进出错开约 0.02 个时间轴单位 —— 五个块挤在 0.008 的间距里会读成"一坨文字掉下来"。

### 5.4 变换预算

| 层 | 属性 | 代价 |
| --- | --- | --- |
| 便宜 | `transform`（位移/缩放/旋转/斜切）、`opacity` | 永远安全 |
| 中等 | `filter: blur/brightness`、`clip-path` | 面积小时可用 |
| 昂贵 | `width` / `height` / `margin` / `top` / `left` | 别动（改 `scaleX`） |
| 极贵 | 大半径 `box-shadow`、缩放中的 `border-radius` | 别在动效里用 |

### 5.5 手绘感 = 量化时钟

想要"手绘/定格"的质感，不是把缓动调怪，而是**把动画量量化到粗网格**：
渲染仍是 30fps，但喂给曲线的 `t` 取 `floor(t * RATE) / RATE`（RATE ≈ 11–15）。
量化的对象是**主体**，不是环境（量化相机 = 看起来像卡顿，量化主体 = 看起来像动画）。

## §6 时间轴铁律（每一条都是踩出来的）

1. **死拍很少是"某一层慢"，而是几层的平台期撞在同一拍**。把轨道按时间横向铺开看，
   别一层一层看 —— 单看每一层都合理，叠起来就有一个洞。
2. **缓动只放在一层**。时间轴本身保持线性：时间是时间，它不该忽快忽慢。
   时间轴缓动 × 元素缓动 = 中段平方、两端更平。
3. **要均匀化的是"眼睛读到的量"，不是几何轴**。擦除/生长按**面积或墨量**配速，
   不按高度、不按元素个数 —— 否则细长的一段一闪而过，宽厚的一段占掉半支片子。
4. **一个窗口只放一件事**。**淡入会吃掉同窗口里的一切**：观众只会报告"有个东西在淡进来"。
   淡入给这一拍的前 ~10%，剩下的时间留给真正要看的东西。
   想说三件事就排成三段（先画 → 再说 → 再交接），不要叠在一起搅。
5. **零速度关键帧后面必然有一拍几乎不动**。这是曲线的定义，不是调参问题。
   要么承认它是"刻意的静止"，并用**另一条轨道**填上这一拍；要么检查是不是某层的时间戳错了。
6. **装置不能比内容活得久**。画框、横线、角标、"向下滚动"这类容器和脚手架，
   必须跟着内容一起退场，且**不要用下一段的开始时间反推它的结束时间**。
7. **指令不能先于它的指涉物**。台词/文字提到的东西必须先画出来 ——
   "抹掉它"不能出现在那条线还没画完的时候。
8. **每一拍都要有一张 money frame**：画面、文字、状态**同时**到位的那一帧。
   这是这一拍存在的理由。如果全片找不到这一帧，这一拍就是废的。
9. **改停留时长，就要在同一个改动里重算与它相关的窗口**（字幕、强调、可交互标记）。
10. **淡入淡出不是节奏，切才是节奏**。全片都靠淡化过渡，观众会读成"一盘幻灯片"。
11. **灵动 vs 飘，是静止比例问题，不是缓动问题**。实测：读起来"活"的参考片，
    约 **50% 的相邻帧几乎相同**（每秒约 15 个新状态）；读起来"飘/飘忽"的版本只有 13%。
    调缓动改不了这个数字，只有两件事能改：**量化时钟**（§5.5）和**在锚点之间也加缓动**。
12. **静止要是主角**。停留在**已经到位、正在被看**的一拍，可以久；
    停留在**没人在看**的一拍，就是死拍。判断标准：眼睛有没有地方可落。

## §7 查重表（撞车即弃，做完新的往里加）

这是一份**骨架**黑名单，不是"效果"黑名单。骨架 = 谁在动 + 怎么动 + 什么时候到位。

| 骨架 | 为什么进黑名单 |
| --- | --- |
| 大数字 + 小标签（数字滚动到值） | 最经典的模板答案；七模板里的 `stat` 就是它 |
| 三栏等宽特性卡（图标 + 名词 + 两行灰字） | 内容不是三个并列时，这就是装饰 |
| 居中标题 + 副标题 + 两个按钮 | 单屏最"生成"的版式 |
| 条形图从左往右依次生长 | 数据在动，但没说任何话 |
| 终端逐字打字 + 光标闪烁 | 已经被用烂到读不出信息 |
| 扫描线 + 暗角 + 漂浮粒子当背景 | "纹理化的空" —— 空是结构问题，不是纹理问题 |
| 每拍都淡入淡出 | 观众把它读成幻灯片 |
| 同一套缓动 + 同一套时长铺满全片 | 读起来就是 CSS 默认值 |
| 同心圆环/雷达扫描当"科技感" | 与内容无关的机制 |
| 紫蓝渐变 + 发光球 | 最可靠的 AI 味标志 |

**要求**：新片子的记忆点（signature）和用过的机制要写回这张表。
一个项目里有几拍必然平凡（数据、字幕、引用），但**整片不能全是这张表**。

## §8 闸门（可测量，命中就改结构）

### 8.1 静帧闸门（关掉动效再判）

把动效停在一帧上推演——先在纸面上想这一帧（只有纸面判断不了的疑问，才用 `vs.py preview --at <秒>` 渲那一帧回答它），然后问：

- [ ] **这一帧单独能不能站住？** 如果它是"居中标题 + 副标题"，不通过。
- [ ] 字号有没有 ≥ 4× 的跳跃？还是全在 16–48px 之间？
- [ ] 焦点是不是只有一个？两行以上的文字有没有被当装饰用？
- [ ] 有没有"因为空而加"的纹理、光晕、飘浮物？删掉它们，空要由结构解决。
- [ ] 版式是双峰（极简或极繁）还是中间那个居中列？

### 8.2 AI 味闸门（逐条过）

- [ ] A1 默认 hero：居中 H1 + 一行副标题 + 两个按钮
- [ ] A2 三栏等宽卡片
- [ ] A3 每一拍内部结构都一样（都是"标题 + 说明"）
- [ ] A4 紫蓝渐变 / 光谱式配色
- [ ] A5 装饰冒充设计（噪点、光晕、飘浮物）
- [ ] A6 没有尺度对比
- [ ] A7 假外壳（手画的浏览器条、假手机框、假 IDE 窗口）
- [ ] A8 编造的证明（"提升 47%""50000+ 用户"）—— 用户没给的数据不许上线
- [ ] B1 统一的 hover/抬升式强调（每拍都给同一种强调）
- [ ] B2 全片统一淡入升起
- [ ] B3 一种缓动、一种时长铺满全片
- [ ] B4 预算全花在开场
- [ ] B5 机制与内容无关（换成别的题目照样能用）
- [ ] B6 只用视差当纵深
- [ ] B7 无意义的跟随光点
- [ ] B8 关掉动效就废掉

### 8.3 多样性与死拍闸门（用工具测）

- `plan` 的 `adjacent_layout_repeats` **必须为 0**；`distinct_layouts` ≥ 3（三拍以上时）。
- `plan` 的 `choreography.worst_gap` 就是一个"死拍"计数：**单拍最长的状态空档**。
  它超过阈值就说明这一拍有一段时间什么都没发生 —— 回去看 §6 第 1、4、5 条。
- `verify` 的 `content` / `motion`：前者只证明"有画面"，后者只证明"在动"。
  **两者都过不代表有设计** —— 这就是为什么静帧闸门必须人工走一遍。

## §9 落到工具上怎么写

1. 给每一拍写一个场景文件，放在工程目录下，例如 `scenes/beat-03.html`，
   然后在 `project.json` 里写：

   ```jsonc
   { "id": "beat-03", "template": "scenes/beat-03.html", "duration": 6.0,
     "data": { "title": "…", "money_frame": 4.2 } }
   ```

   `scene` 按**工程目录**解析（早期版本的 `template:` 名称是按进程 cwd 解析的，同一个工程在
   一个目录下能渲染、换个目录就报找不到，那个坑已经修掉了）。
2. 场景必须暴露 `window.seek(t)`，并在结尾置 `window.__sceneReady = true`；
   `Scene` / `Anim` / `Kit` 由渲染器注入，**不要**在场景里写 `<script src>`：场景会被复制进
   工程，相对路径会断。直接用 `Scene.mount()`，需要关键帧就用 `Anim.Scene`，需要舞台/相机/
   粒子就用 `Kit`。
3. 写之前先 `python vs.py shots "<这一拍的 intent>"`：拿三个结构不同的候选，各做到 pass 1，
   用 `rehearse` / `scrub` 横向比一次，按 §1.5 的闸门选一个（落选的写进 §7），再往 pass 2-5 走。
4. 写完先在纸面上过 §8.1 的**静帧闸门**（非必要不 `preview`；确有判断不了的疑问才渲那一帧），
   再 `plan` 看预算与多样性，最后 `run` 跑验收。任何一项不过，**改编排，不要改验收标准**。
